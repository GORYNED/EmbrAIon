# Project Overlay (Проектный слой)

Подключаемый репозиторий хранит конфигурацию EmbrAIon в каталоге `.embraion/`.

Назначение файлов:

- `project.yaml` — репозиторий/версия EmbrAIon, идентичность проекта и `capabilities`;
- `knowledge.yaml` — ссылки на проектные знания и метаданные выбора контекста;
- `policy.yaml` — source classes, review policy и privacy;
- `routing.yaml` — необязательные model/effort/options overrides;
- `validation.yaml` — профили валидации;
- `agents.yaml` — специфичные для проекта агенты.

Проектный слой может добавлять более строгие правила, но не должен скрытно ослаблять жёсткие ограничения Core (Ядра).

## Автоматический выбор версии

Для обычных команд глобальный launcher находит ближайший `.embraion/project.yaml`, читает `framework.version` и сравнивает её со своей версией. Если версии отличаются, EmbrAIon создаёт изолированный runtime в `~/.embraion/versions/<version>/` и устанавливает туда точный пакет `embraion==<version>` из PyPI.

После этого команда выполняется нужной закэшированной версией. Поэтому на одном компьютере может быть один глобальный launcher, а разные репозитории могут оставаться на разных релизах EmbrAIon.

`embraion init` и `embraion update` намеренно не передаются project runtime:

- `init` создаёт модульную конфигурацию и записывает версию глобального launcher;
- `update` меняет pin только текущего репозитория;
- `--framework-version` позволяет явно выбрать конкретный релиз.

Переменная `EMBRAION_HOME` является явным override для разработки и отключает автоматическое делегирование версии для текущего процесса.

Сам репозиторий проекта остаётся каноническим источником продуктовой спецификации, архитектуры, контрактов совместимости, результатов валидации и предметных знаний.
