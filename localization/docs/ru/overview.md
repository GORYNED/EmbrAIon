# Зачем нужен EmbrAIon

EmbrAIon — **AI-First Engineering System** для программных репозиториев.

Он не делает модель «умнее» сам по себе. Его задача — сделать разработку с ИИ **повторяемой, проектно-осознанной, проверяемой и переносимой между сессиями и AI-клиентами**.

## Какую проблему он решает

В реальном проекте ИИ должен помнить не только текущий prompt, но и:

- где находится архитектурная истина;
- какие файлы нельзя менять;
- какие данные можно передавать наружу;
- какие роли и специалисты существуют;
- как выбирать модели для разных классов задач;
- какие тесты обязательны;
- когда нужен независимый review;
- какое evidence должно существовать перед merge.

Без системы эти правила размазываются по prompt'ам, `AGENTS.md`, настройкам Codex/Copilot, CI, скриптам и памяти разработчика.

EmbrAIon превращает их в один проектный контракт.

## Простая ментальная модель

> **EmbrAIon — операционная система AI-разработки, а `.embraion/` — Settings конкретного проекта.**

Это аналогия. EmbrAIon не является буквальной ОС и не перехватывает каждый prompt.

Разделение такое:

- **EmbrAIon Core** владеет переиспользуемыми механизмами;
- **проект** хранит свои факты и настройки в `.embraion/`;
- **AI host** (Codex, Copilot, Claude Code) ведёт разговор, reasoning и использует свои инструменты.

## Как выглядит обычная работа

Вы пишете обычную задачу:

> Исправь reconnect при потере соединения и добавь regression test.

AI-клиент уже видит сгенерированные EmbrAIon agents/skills и знает, где лежат настройки проекта. Он может применить project knowledge, policy, routing, validation и review contract без того, чтобы вы каждый раз вручную перечисляли всё заново.

## Конфигурация тоже может быть разговорной

Можно написать:

> Настрой routing: bounded-задачи оставляй дешёвыми, complex отправляй на более сильный deployment, critical используй только для исключительного риска.

AI должен сам понять, что source of truth находится в `.embraion/routing.yaml` и, при необходимости, `.embraion/deployments.yaml`.

Цель не в том, чтобы пользователь выучил YAML. Цель в том, чтобы **ИИ знал, куда правильно записывать настройки проекта**.

## Что EmbrAIon не делает

EmbrAIon не является:

- runtime-зависимостью готового приложения;
- заменой Codex/Copilot/Claude Code;
- обязательным proxy для каждого prompt;
- глобальным каталогом моделей;
- заменой архитектуры, тестов или product specification;
- системой, которая молча устанавливает CI/hook'и.
