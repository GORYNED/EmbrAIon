# Planning

## Procedure

1. Resolve the requested outcome and canonical project truth.
2. Identify ambiguity, affected capabilities, ownership boundaries, compatibility surfaces, privacy class, and validation impact.
3. Choose the smallest useful set of roles and skills.
4. Decide whether structured specification work would materially improve the task.
5. Define acceptance criteria, dependency order, writable ownership, and validation depth.
6. Return a compact execution plan with explicit risks and unresolved questions.

## Guardrails

- Do not turn planning into speculative implementation.
- Do not broaden scope to unrelated cleanup.
- Do not choose a concrete model merely because a role was selected.
- Prefer current authoritative project evidence over assumptions.
