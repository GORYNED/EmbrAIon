# Review

The canonical [Lead contract](../agents/lead.yaml) owns orchestration and final acceptance. Apply this workflow to every pull request and every substantial implementation under the [independent review rule](../rules/review.md), or when stricter project policy requires it. Keep trivial non-PR work proportional.

1. The author finishes the implementation candidate, including intended tests, documentation, and generated artifacts. Identify the full cumulative diff against the PR base (or the relevant starting state for non-PR work), related contracts, code, and tests.
2. Complete all checks required by the candidate's impact and project policy, including required CI for a PR. Record fresh results against the current candidate. Explicitly identify checks legitimately not required by impact under validation policy. Pending, missing, failing, stale, or unavailable required evidence blocks review readiness; never waive a required check or treat a skip as a pass.
3. The author self-reviews the full cumulative diff and related code for correctness, regressions, compatibility, security, privacy, and acceptance criteria. Check for unintended edits (formatting churn, debug leftovers, stray files, accidental renames) and that each claim in the description is true of the current head. Fix findings and repeat affected required checks and the self-review until clear. Only then freeze the candidate for independent review.
4. Lead resolves a fresh Reviewer assignment through the existing project role/task routing and deploys a different read-only agent from the author or remediator in the same authorized execution host. Verify the exact resolved host, model, effort, options, access, and effective settings under the [orchestration skill](../skills/orchestration/SKILL.md). Do not substitute Lead's review, a different host, an undeclared fallback, or an unavailable capability. Block readiness if the required assignment cannot run.
5. Give Reviewer the intent and acceptance criteria, PR source HEAD SHA and reviewed base/diff, full cumulative diff, related contracts/code/tests, current required-check and CI evidence, explicit not-required checks, and known risks. Reviewer checks the whole candidate and reports prioritized findings with evidence or an explicit no-material-findings result. If clear, Reviewer explicitly confirms the current full PR source HEAD SHA, reviewed base/diff, and evidence. Missing required evidence is not a pass.
6. The author or another implementation owner, never the read-only Reviewer, resolves findings following the [handling-review-findings skill](../skills/handling-review-findings/SKILL.md). After each change, rerun affected required checks and self-review the updated cumulative candidate before a freshly resolved Reviewer assignment. The new review may focus proportionally on the delta, but must check the cumulative final state and explicitly confirm its current full PR source HEAD SHA, reviewed base/diff, and current evidence. Classify the actual new assignment; prior complexity is risk evidence, not an inherited route.
7. Any later candidate content or commit change, including cosmetic or metadata changes, or a change to the reviewed base/diff or required evidence, invalidates confirmation. Repeat affected checks, author self-review, and independent confirmation before claiming review complete. Immediately before an authorized squash merge, verify that the PR source HEAD and reviewed diff still match the confirmed candidate; the merge's new squash commit SHA is not itself the pre-merge review target.
8. Lead integrates review and validation outcomes before final acceptance. Reviewer confirmation never grants merge or release authority. Apply existing user approval and human merge rules; do not require a hosted bot review or an external cross-host review by default.
