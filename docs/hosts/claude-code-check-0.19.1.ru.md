# Проверка Claude Code 0.19.1 на Windows

Дата: 2026-10-03. Фреймворк: EmbrAIon 0.19.1. Хост: локальное приложение Claude Code Desktop на Windows 11.

## Источник свидетельств

Этот исторический отчёт сохраняет результаты двух отдельных локальных сессий в worktree, переданные сопровождающим. Автор документации EmbrAIon не изучал исходные транскрипты хоста и не повторял эти Desktop-сессии. Наблюдения ниже сохраняют это происхождение; документ не является независимо подтверждённым свидетельством выполнения.

Исходные транскрипты и журналы hooks остаются приватными. Названия репозиториев, локальные пути, идентификаторы коммитов, сессий и агентов, исходные payload и приватные ссылки на Threads исключены. Модели и effort ниже описывают проведённые проверки, а не умолчания фреймворка или инструкции по роутингу.

## Как проходила проверка

Обе сессии использовали worktree из актуального main, пин проекта и runtime 0.19.1, действующие инструкции репозитория и проецируемый навык orchestration. Lead разрешил ограниченное задание Reviewer с доступом на чтение, выбрал точный профиль с хешем из загруженного реестра Thread и вызвал его без переопределения модели. Подготовленный план dispatch запуском не считался.

Reviewer проверял сведения о проекте и назначения нативных агентов. Это ограниченная проверка конфигурации, а не полное ревью кода или проверка всех защитных границ. В обоих отчётах указаны чистое рабочее дерево и отсутствие PR, merge, release и синтетических событий hooks.

## Переданные результаты

| Наблюдение | Сессия A | Сессия B |
| --- | --- | --- |
| Пин и runtime | 0.19.1 | 0.19.1 |
| Scoped-профиль | Загружен и вызван без override | Загружен и вызван без override |
| Модель в транскрипте хоста | Sonnet 5.5 | Opus 5.5 |
| Настроенный/запрошенный effort | medium | high |
| Журнал в активном worktree | Новые соответствующие PostToolUse и SubagentStop | Новые соответствующие PostToolUse и SubagentStop |
| Состояние callbacks | none до запуска; recorded после | recorded после запуска |
| Сравнение переданного effort | match | match |
| Результат Reviewer | Несогласованностей в ограниченном объёме нет | Существенных замечаний в ограниченном объёме нет |

Сопровождающий сообщил о совпадении идентификаторов сессии и агента, типа scoped-профиля и digest определения в новых записях журнала worktree. Наличие журнала проверялось в активном worktree; эти отчёты не устанавливают отсутствие копий в других папках.

Модель определялась по транскрипту субагента, который записывает хост, отдельно от журнала observer и слов самого агента. Для сессии B также передано поле effort из транскрипта: оно отражает запрошенную настройку и не доказывает её фактическое применение API.

## Выводы и ограничения

Отчёты подтверждают на уровне переданных наблюдений нативный запуск загруженных профилей Reviewer и запись callbacks в активный worktree на проверенном Windows-хосте. Они также содержат переданные сопровождающим сведения о выбранных моделях из транскриптов хоста.

Observer корректно сохранил `execution`, `model` и фактический `effort` как `unverified`, а источник — `unverified-command-input`. Его публичная команда принимает JSON: `callbacks: recorded` и `reported-effort: match` описывают принятые метаданные, но не доказывают происхождение от хоста, успешное завершение или фактический effort. Источники наблюдений остаются раздельными.

`.claude/embraion-native.json` хранит назначения и идентичность определений; это не источник версии фреймворка. Пин, артефакт и runtime проверяются отдельно. Reviewer с доступом на чтение не требуется shell или инструмент хеширования: Lead может проверить точное содержимое проекций канонической командой.

Эти две проверки не охватывали облако, macOS, возобновлённые Threads, отрицательные проверки guard и effort агентов с правом записи. Исторический результат не подтверждает следующий Thread, изменённую конфигурацию или другую сборку хоста. Фактический effort остаётся неподтверждённым.

## Как повторить короткую проверку

1. Откройте новый локальный Thread в актуальной копии репозитория или worktree. Прочитайте применимые инструкции и проверьте совпадение пина и runtime. Если hooks запускаются из другой копии, её пин runtime и lock артефакта должны быть совместимы с worktree события.
2. В активном worktree выполните `embraion framework install`, `embraion --version`, `embraion route --validate` и `embraion projection verify --host claude-code --component agents --component skills --component scoped-agents`.
3. До запуска сохраните результат `embraion claude-native status`. Разрешите ограниченное ревью через существующую роль, маршрут и правила приватности/доступа проекта.
4. Вызовите точный возвращённый scoped-тип из загруженного реестра без override модели. Передайте только нужные для этой проверки файлы конфигурации.
5. После завершения выполните status в том же worktree и проверьте новые записи журнала, соответствующие этому запуску. Исходные записи и идентификаторы храните локально; синтетические callbacks не создавайте.
6. При наличии изучите сведения о модели от хоста и отделите запрошенный effort от фактического. Неподтверждаемые поля оставляйте unverified.

Установка и семантика observer описаны в [руководстве Claude Code](claude-code.md), готовность производственного PR и отдельные разрешения на merge/release — в [порядке ревью](../guides/runs-review.md).
