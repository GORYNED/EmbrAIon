# Необязательные возможности Unity

Необязательное расширение `unity` содержит оригинальные процедуры EmbrAIon для инженерной работы с Unity. Его манифест находится в `extensions/unity/manifest.yaml`. Расширение отделено от универсального Core и не меняет Unity-проект без намеренного подключения. Версия Unity, структура сборок, стандарт кода, форматы сохранения, целевые платформы и команды проверки определяются самим проектом. Эти процедуры не устанавливают Unity, AI-плагин или пакеты проекта.

| Навык | Когда применять | Какие свидетельства сохранять |
| --- | --- | --- |
| `unity-serialization-migration` | Меняется сериализованное поле, тип, ассет, namespace или сборка | Карта старых/новых идентичностей, реальные ассеты, результаты миграции и восстановления |
| `unity-lifecycle-review` | Меняется время жизни callback, подписки, async-задачи, объекта из пула или нативного ресурса | Соответствие владельца и освобождения, результаты подходящих Play Mode проверок |
| `unity-player-validation` | Требуется доказать поведение Player или целевой платформы | Версия Unity, сборка/backend/платформа, фактические результаты Editor, build и Player |
| `unity-asset-audit` | Нужно проверить указанную область ассетов или неисправную ссылку | Ограниченные по области находки, затронутые потребители и проверенные исправления |

Unity хранит ссылки в ассетах и метаданных, а не только в исходниках C#. При переносе сохраняйте GUID и файлы `.meta`; перед миграцией проверяйте сериализованные типы и поля, включая случаи `SerializeReference`. Для правок сериализованных ассетов по возможности используйте Unity Editor API или официальные инструменты, уже доступные проекту. Отдельно установленный официальный плагин Unity может предоставить такой доступ, но это внешняя интеграция с собственными проверками установки и прав доступа. EmbrAIon не включает и не копирует его закрытые навыки.

Результаты Editor, сборки и Player отвечают на разные вопросы. Результат Editor не доказывает работу IL2CPP stripping или устройства, а успешная сборка Player не доказывает поведение во время исполнения до запуска Player. Для изменения только документации выполнение Unity обычно не нужно, если этого не требует проект. Общий процесс описан в [инженерных навыках](engineering-skills.ru.md), а структура репозитория — в [примере Unity](../examples/unity.ru.md).

Манифест расширения является индексом пакета, а не доказательством загрузки навыков конкретным хостом. После подключения проверяйте установленную версию фреймворка и проекцию хоста. Для установки в конкретный репозиторий следуйте его согласованному проектному overlay и процессу установки хоста; сведения о проекте храните в overlay.
