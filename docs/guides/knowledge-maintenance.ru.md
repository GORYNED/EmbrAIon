# Поддержка знаний

Связи документа с исходными файлами можно объявить в необязательном `.embraion/knowledge-maintenance.yaml`:

```yaml
documents:
  - id: architecture
    path: docs/architecture.md
    sources:
      - src/app.py
```

Пути должны указывать на обычные файлы внутри проекта. Документ может иметь несколько исходных файлов. Поле `observed-version` задаётся только при фактическом наблюдении версии внешнего источника; без него изменение внешней версии остаётся неизвестным. Даты и статус проверки не выводятся из времени изменения файлов.

После проверки объявленных связей явно вызовите API Python `snapshot_knowledge(project=...)`. Он сохраняет только пути, хеши, ID, необязательную наблюдаемую версию и время создания базового снимка в игнорируемом `.embraion/state/knowledge-audit/baseline.json`. `audit_knowledge(project=...)` только читает снимок и возвращает `current`, `needs-review`, `missing` или `unconfigured`. Изменение исходного файла, документа, наблюдаемой версии или конфигурации требует проверки. Аудит не переписывает документацию, не создаёт новый базовый снимок и не продвигает результаты обучения. Новый снимок заменяет прежний лишь после явного запроса и проверки.

Существующие процессы выборки контекста и обучения остаются отдельными. Хеши контекста показывают, какие знания были выбраны для задачи; аудит сравнивает объявленные документы с их источниками. Кандидаты обучения носят рекомендательный характер до прохождения действующего процесса утверждения. Эта функция не создаёт периодическое расписание.
