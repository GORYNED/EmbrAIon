# Внешние возможности

Внешние возможности описываются в необязательном файле проекта `.embraion/external-capabilities.yaml`. Он содержит сведения о программах и функциях хоста, которые могут понадобиться проекту. Правила EmbrAIon Core и контракты проекта сохраняют приоритет. По умолчанию файла нет; это означает пустой список. Описание не устанавливает программы, не загружает исходники, не включает плагины хоста, не расширяет доступ и не доказывает выполнение навыка.

Для списка действует строгая версионированная [схема](../../schemas/external-capabilities.schema.json). Управляемый пакет входит в закреплённую версию EmbrAIon. Возможность типа `host-managed` устанавливается и контролируется отдельно, пользователем или AI-хостом. В каталог навыков хоста можно перенести только выбранные встроенные навыки, перечисленные в манифесте. Возможности `host-managed` служат только для диагностики; EmbrAIon никогда их не копирует.

```yaml
schema-version: 1
capabilities:
  - id: unity
    kind: managed-bundle
    source: builtin:unity
    version: 0.20.0
    license: MIT
    hosts: [codex]
    host-requirements: {codex: [skills]}
    env-vars: []
    access: workspace-write
    data-class: PRIVATE
    selected-skills: [unity-asset-audit]
  - id: spec-kit
    kind: host-managed
    source: https://github.com/github/spec-kit
    version: 1.2.3
    license: MIT
    hosts: [codex]
    host-requirements: {codex: [plugins]}
    env-vars: []
    access: external-execution
    data-class: PRIVATE
```

Для каждой записи нужны уникальный ID, тип, источник, точная `version` **или** `digest` в формате `sha256:`, лицензия, список `hosts`, *имена* переменных среды в `env-vars`, уровень `access` и `data-class`: `PUBLIC`, `PRIVATE` либо `CONFIDENTIAL`. Необязательное поле `host-requirements` перечисляет требуемые функции заявленных хостов; диагностика показывает эти имена, но не может проверить их локально. Значения доступа: `read-only`, `workspace-write`, `external-execution`. Поддерживаемые хосты: `codex`, `claude-code`, `copilot`. Не записывайте сюда учётные данные, значения токенов, аргументы команд или значения конфигурации хоста. URL источника должен содержать обычный путь HTTPS-репозитория без учётных данных, параметров запроса и фрагмента. Идентификатор хоста может иметь вид `host:<identifier>`.

Для `builtin:unity` ID должен быть `unity`, а `version` должна точно совпадать с закреплённой версией проекта и работающей версией фреймворка. `selected-skills` должны присутствовать в `extensions/unity/manifest.yaml`; версия и лицензия манифеста должны совпадать. Исходный каталог каждого навыка находится внутри `extensions/unity/skills/<skill-id>` и содержит `SKILL.md`. Отсутствующий, несовпадающий или небезопасный источник прерывает проекцию. Встроенные навыки Unity входят в EmbrAIon; они не устанавливают редактор Unity или сторонние инструменты. Запись `host-managed` не может выбирать навыки для проекции.

Диагностика различает шесть стадий: `declared`, `installed-config`, `host-discovered`, `instructions-read`, `tools-ready`, `executed`. Чтение списка подтверждает только `declared`. Для встроенного пакета можно проверить `installed-config` по манифесту закреплённого фреймворка и файлам выбранных навыков. Для возможностей `host-managed` и последующих стадий нет подключения к работающему хосту. Эти стадии остаются `unverified`, пока переданный отчёт наблюдения не заявит об их наличии; принятые заявления помечаются `self-reported`, а не подтверждаются. Описанный источник, наличие переменной среды или заявленное событие JSON не доказывают загрузку хостом или выполнение. Без достоверного наблюдения работающего хоста значение `ready` остаётся `false`.

Вызывающая сторона может передать ограниченный отчёт наблюдения для диагностики без записи файлов. Он должен содержать `schema-version: 1`, точный `scope`, возвращённый `observation_scope(...)` или диагностикой, целевой `host`, время `observed-at` в формате ISO с часовым поясом и записи с точными `id`, `source`, `version-or-digest` и заявленными `stages`. Отчёты старше 24 часов, более чем на пять минут из будущего, с другой идентичностью списка или неизвестными полями игнорируются. `scope` связывает абсолютный путь проекта, версию фреймворка, хост и список; это контрольная сумма идентичности, а не аутентификация. Даже актуальный отчёт с верной областью остаётся самостоятельным заявлением. Проверка переменных среды возвращает только имена и признак наличия; значения никогда не выводятся.

Команда `embraion capabilities --path <project> --host codex --json` показывает диагностический список. `--observation <report.json>` передаёт отчёт; команда не обнаруживает плагины хоста и не запускает инструменты. Отсутствующие или неоднозначные сведения о требуемой возможности не считаются готовностью.
